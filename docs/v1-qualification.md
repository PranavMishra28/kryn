# Supervised v1 qualification

This suite qualifies KRYN as a human-supervised local coding workspace on the stated Apple Silicon profile. It does not qualify unattended application building, frontier parity, independent Reviewer authority or useful reasoning across the entire configured 96K window. Preserve raw private traces outside Git and publish a bounded receipt for every attempted gate, including failures. A model's completion text cannot substitute for a check result.

Run against the **final committed release candidate and its built wheel** on the normally occupied owner Mac. Record source SHA, package SHA256, installed payload manifest, OpenCode/oMLX/model identities, power state, active applications, memory-pressure and swap samples, commands, observed results and any operator interventions. Do not count interrupted or repaired attempts as autonomous success. A supervised pass may include operator review and correction, but record both.

| Gate | Passing observation | Evidence |
|---|---|---|
| Coding/edit/test | In a disposable Git project, Agent reads an existing file, makes a bounded edit, runs an actual imported-code check and inspects the current diff. The operator verifies the behavior and can reject incorrect work. | Native session/tool trace, source-bound check exit, current diff and independent operator result. Run boundary probes against the full task contract even when the frozen TaskboardLite 02 or 03 grader passes. |
| Browser/search | Native browser and search MCP servers connect. On a disposable local page, an actual browser opens and exercises a visible success and error path at normal and narrow widths. A search returns a current primary source URL. | Native tool receipts and independent browser observations. Search availability is distinct from offline local coding. |
| Unsupported claims | A deliberately incomplete or failing disposable task receives a failing check. The development Acceptance Controller reports blocked and does not promote the agent's success prose. | Controller state, exact check exit and source revision; its offline tests alone are mechanism evidence. |
| Compaction/restart | Two actual OpenCode compactions and a fresh server/client process occur in one saved supervised project. The continued session retains the user goal and failed checks, labels completion unverified, detects a file changed outside the checkpoint, and reaches a correct next action after operator review. | Native compaction/session IDs, checkpoint content, before/after Git hashes, resumed tool/check results and operator review. A synthetic hook test alone is insufficient. |
| Resource safety | The unchanged daily-use guard records warning pressure but stops critical pressure, excess swap, missing telemetry or a changed listener without touching unrelated sessions. The owner can resume its saved project after pressure settles. The separate strict research guard refuses non-green preflight and sustained warnings. | Guard samples, native session preservation and recovery result; do not force the host into unsafe pressure to produce a receipt. |
| Final artifact lifecycle | Build a clean wheel from the final commit, verify its manifest and hashes, install/update the owner from those bytes, check terminal and GUI startup plus saved-session migration, roll back, reactivate, and check uninstall/reactivation in an isolated owned path. Anonymous download of the *published* assets is a final post-release check. | Wheel/installer SHA256, transaction receipts, `doctor --deep`, startup/rollback evidence and published asset hashes. |
| Sustained supervised use | A representative multi-stage coding project remains useful under the guard for 45–60 minutes of **active** work, including checks, at least one UI inspection when relevant and a saved-session continuation. Record corrections and downtime separately. | Per-stage accepted outcomes, tool traces, elapsed active duration, host pressure/swap and final independent review. Idle time does not count. |

`make check` and `make package-smoke` are required offline regressions, not substitutes for the live gates. The frozen autonomous coding/UI suite remains in [`evals/`](../evals/README.md) with its failed results. The v1 decision uses this supervised contract and records the distinction in [current status](../plan.md). Release only after the applicable rows pass from the final artifact; describe any unqualified capability plainly.

For disposable supervised native trials, `run_native_trial.py --daily-use-guard` mirrors the interactive launcher's resource policy: warning pressure is recorded, while critical pressure, missing telemetry, listener changes and more than 512 MiB swap growth stop the owned session. The existing `--guard-resources` mode remains the stricter research screen and still refuses sustained warning pressure. A daily-use pass with warnings must disclose them; it does not establish warning-free operation.
