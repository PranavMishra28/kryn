# Long-workflow protocol for the fresh review-queue task

Use one fresh `prepare` run and its workspace throughout. The operator releases the following stages separately in one native OpenCode session; no operator repair hints are supplied after launch. Keep transcripts, actual prompts, tool results, timestamps and resource telemetry outside the workspace under that run's `evidence/`. The fixture's `TASK.md` is the full contract; these stages only schedule work.

1. **Plan and backend:** Inspect the fixture, record criteria, implement persistence and both review API methods, and run backend checks. Record the Git state, files changed, exact test output, unresolved browser work and next action. Cause or wait for the first *actual native compaction* while useful work is in progress. Save the native compaction event and resumed action; a written summary without a compaction event does not count.
2. **Browser work:** Continue from current files, implement the filter and review controls, and perform browser checks with the live server. Save screenshots, DOM/console/network evidence, failed criteria and changes made after the first compaction. Stop the owned OpenCode client/server process using its supported restart path, then start a fresh process and reopen the same native session. Keep the fixture server/database only as long as needed for browser evidence. Save process identity before/after and the first resumed tool result.
3. **Recovery and repair:** Reinspect current Git status, relevant files and check outputs after the restart. Make the next needed change; do not trust a summary's claimed pass. Cause or wait for a second *actual native compaction* while this stage still has work. Save its event, prompt size, resumed action and current file/check evidence.
4. **Acceptance and audit:** Run the independent verifier against the final workspace. Capture the fresh read-only review with actual diff, non-ignored untracked files, test output and browser evidence. Resolve material findings, rerun affected checks and independently verify again. The final report distinguishes attempted, mechanically tested and independently accepted criteria and gives active work duration excluding idle waits.

For the long-run gate, the external review must identify two distinct native compaction event IDs/times, one real process restart with prior and resumed PIDs/session ID, bounded current-state checks after each transition, useful work across all stages, and active duration. The independent verifier grades source/API/browser behavior; the operator review grades the continuity, review and truthful-completion evidence. An internal green test or an agent's completion claim cannot substitute for either.
