# KRYN status — 1 October 2026

KRYN is usable today for supervised coding on this Mac. The installed daily profile is OpenCode 2.0.10, oMLX 0.6.4 and Qwen3.5-9B-6bit with a guarded 96K configured context, 8K output limit and 22 GiB process ceiling. Run `kryn` from a project directory, `kryn --web` for the GUI, `kryn doctor` for health, and `kryn rollback` for recovery. [Installation and controls](README.md) · [Exact profile](setup/accepted-profile.json).

The published [v0.2.0 preview](https://github.com/PranavMishra28/kryn/releases/tag/v0.2.0) remains a rollback point. The repository is now public, and its credential-free installer and release hashes passed an [anonymous download check](evals/history/2026-09-30-public-distribution-and-reviewer-diagnostic.json). A same-version private build from `0541390` is active on the owner Mac after [transactional install, rollback and reactivation](evals/history/2026-09-30-private-ui-incident-activation.json). Its launcher and Python environment live in persistent LocalAI app data; a guarded protocol smoke and deep integrity check passed after the temporary build was removed. **Public releases, tags and version bumps are paused.** Current `main` and private candidates are not an automatic update channel. Passing installation or a small coding task does not qualify autonomous application building, accurate review, useful 96K context or frontier-level quality.

## Model decision

The installed 9B remains the settled daily default because it is the only model with checked owner installation and rollback. Do not reopen the model, quantization, or context choice for incremental benchmark results; require a material improvement on independently accepted work and all resource and lifecycle gates before reconsidering it. An isolated oMLX 0.7.0 Qwen3.6-35B-A3B 3-bit candidate is the strongest **screened** coding profile: frozen Task03 passed in 102–114 seconds versus 583 seconds on the owner 9B, with normal sampled pressure and no swap growth. Staged Task06 passed independent browser checks, but Task12 failed independent UI acceptance at both 64K and 49K. The 49K Fast and normal trials stayed under the guard; each falsely claimed completion despite the same stored-text bug, and neither completed the required review/restart sequence. Its 64K normal retry and repeated 80K probe hit resource limits. A Qwen3.6 2-bit retest passed protocol and Task03 but violated evaluator control on Task06 and failed mobile layout; a GLM-4.7-Flash 3-bit conversion failed answer/tool protocol. The 27B 4-bit and 35B 4-bit candidates were less suitable on this occupied 48 GiB Mac. [Initial comparison](evals/history/2026-09-30-local-model-comparison.json) · [Follow-up, including raw paths](evals/history/2026-09-30-model-selection-followup.json). **No alternate model is promoted.**

[The model and benchmark protocol](docs/evaluation.md) freezes the native stack and independent checks. Select on hard acceptance first: protocol/tool round-trip, actual code and browser outcome, accurate completion/review, compaction/restart, and green memory/swap. Only compare useful speed among profiles that pass those gates. Publisher benchmark tables and a larger declared context are candidate hints, not KRYN results. The current public fixture is a development regression set; a fresh private holdout is needed before a default change. The native-trial route checker now recognizes KRYN's deterministic compactions without a fictitious HTTP call; replay corrected the 49K Fast trace to 115 routed model generations plus two checkpoints, without changing its failed UI verdict.

## Update awareness

The installed client checks published releases and can offer **Update and restart / Later** while idle. It verifies the selected tag and wheel hash again before transactional activation and resumes the project; `/update`, `kryn update --check`, and `kryn rollback` are available. The 0.1.10-to-0.2.0 terminal route and owner rollback passed. A real future-release TUI acceptance/resume remains unqualified because no newer published release exists. [Update receipt](evals/history/2026-09-27-update-awareness.json). Keep the release pause until the failed gates above pass.

## Incident capture and promotion

`kryn report` and `kryn improve failures` show bounded private execution/check failures and UI edits without observed browser work. They do not prove diagnosis or repair. A proposed extra model-driven UI continuation was rejected after the [live diagnostic](evals/history/2026-09-30-ui-verification-candidate-rejection.json) showed no benefit and an independent browser failure. The optional learning worker remains **paused** and has shown no application-building benefit. Promote a change only after reproducing the real failure, retaining failed evidence, independently grading a fresh candidate and baseline on matched tasks, reviewing the diff, and checking owner install/rollback. No automatic self-modifying path is qualified. [Mechanics](docs/usage.md#improvement-from-actual-failures) · [Evidence lineage](evals/history/2026-09-27-check-failure-lineage.json).
